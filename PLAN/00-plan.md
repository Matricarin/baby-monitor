# План разработки — Baby Monitor

План опирается на [дизайн](./00-baby-monitor.md). Цель: рабочая радионяня дома за ограниченный срок, с понятным для вас кодом.

## Исходные условия

| Фактор | Решение в плане |
|---|---|
| ASP.NET Core — джун+ | Backend ведёте вы; сложные куски (медиа, деплой) — с агентом, но с разбором «почему так» |
| React — trainee | UI минимальный (2 экрана); каркас/типовые паттерны может набросать агент, логику экранов правите/понимаете вы |
| Windows + Docker | Основная разработка и проверка без Pi |
| Доставка на Pi по USB | Артефакт: self-contained publish `linux-arm64` (+ конфиг) на флешку; на Pi — распаковать и запустить |
| Не растягивать | Жёсткий MVP за **4 недели**, буфер **+1 неделя**; после MVP — только must-have polish |

**Интенсивность (заложена в сроки):** ~8–12 часов в неделю (вечера). Если больше — сжатие до ~3 недель реально.

## MVP (что считаем «готово»)

Обязательно к концу недели 4:

1. Вход по паролю (cookie/session).
2. Экран live: видео **и** звук в LAN, latency в пределах 2–4 с (или явно измеренная и приемлемая).
3. Mute звука на клиенте.
4. Переключатель «ночной режим» (клиентский фильтр + по возможности пресет камеры).
5. Вкл/выкл записи на диск, кольцо ~1 час.
6. Скрипт/инструкция: собрать на Windows → скопировать по USB → запустить на Pi.

**Не в MVP:** HTTPS, красивый UI, алерты, IR-камера, Telegram, доступ извне, идеальный night vision.

## Принцип работы с агентом

Чтобы разбираться в своём проекте:

- **Вы** принимаете решения по структуре solution, API, auth, именам, flow экранов.
- **Агент** помогает со spike медиа, Docker, деплоем, React-boilerplate, отладкой блокеров.
- После каждой «агентской» сессии — короткий **checkpoint**: 5–10 мин своими словами объяснить, что сделано и как это устроено (можно в конце фазы в этот файл).
- Не отдавать агенту весь проект «сделай всё»: один этап = одна понятная цель.

## Фиксация технического решения (до кодирования UI)

До старта фазы 2 зафиксировать транспорт стрима (иначе риск переделок):

| Вариант | Для вашего скилла | Рекомендация |
|---|---|---|
| **A. FFmpeg + MediaMTX (или аналог) + ASP.NET как API/UI** | Проще понять границы: медиа отдельно, ваш код — auth и кнопки | **Выбрать для MVP** |
| B. Всё в ASP.NET (WebRTC/SIPSorcery) | Сложнее отладка на джун+ | Отложить после MVP |

На Windows в Docker: тестовый паттерн / файл вместо камеры; на Pi — `/dev/video0` + mic C270.

## Календарный план

```text
Неделя 0 (2–3 вечера)  Spike + каркас
Неделя 1               Backend skeleton + auth + Docker
Неделя 2               Live A/V (главный риск)
Неделя 3               React UI + управление
Неделя 4               Запись + деплой на Pi по USB
Неделя 5 (буфер)       Стабилизация на реальном железе
```

---

### Неделя 0 — Spike и каркас (2–3 вечера)

**Цель:** убедиться, что live A/V на выбранном пути вообще поднимается; заготовить репозиторий.

| Задача | Кто | Зачем вам |
|---|---|---|
| Поднять FFmpeg (Windows/Docker): файл/паттерн → HLS или WebRTC preview в браузере | Агент ведёт, вы рядом | Увидеть пайплайн до «своего» кода |
| Выбрать вариант A и записать в дизайн (закрыть открытый вопрос про транспорт) | Вы | Одно решение на весь проект |
| Создать solution: `Api` (ASP.NET) + `Web` (React+Vite+TS) | Вы (+ агент на шаблон React) | Привычная структура |
| `docker-compose` для API (+ позже media) | Вместе | Единый способ запуска на ноуте |

**Done:** в браузере на Windows виден тестовый поток; в доке зафиксирован транспорт; пустой API отвечает на `/health`.

**Срок:** 3–4 дня календарно.

---

### Неделя 1 — Backend и доступ

**Цель:** сайт с паролем, без медиа в проде ещё.

| Задача | Кто |
|---|---|
| Cookie auth: один пароль из конфига (`appsettings` / env) | Вы |
| API: `POST /login`, `POST /logout`, `GET /me` | Вы |
| Раздача React build из ASP.NET (или proxy в dev) | Вместе |
| Экран Login (простой) | Вы; агент — если застряли на React/роутинге |
| Защита API атрибутом/middleware | Вы |

**Done:** без пароля стрим/управление недоступны; с паролем — заглушка «скоро трансляция».

**Учёба:** session cookie, CORS в LAN, отличие dev-proxy vs production static files.

---

### Неделя 2 — Live видео + звук (критический путь)

**Цель:** после логина реально смотреть/слушать поток в LAN (пока хоть с тестового источника в Docker).

| Задача | Кто |
|---|---|
| Media-сервис в compose (MediaMTX/FFmpeg) | Агент + ваш разбор конфига |
| ASP.NET не «рисует» кадры, а отдаёт URL/сигнал стрима и команды | Вы |
| React: `<video>` / плеер под выбранный транспорт | Вместе (агент — wiring, вы — экран) |
| Mute на клиенте | Вы |
| Проверка latency грубо (секундомер / хлопок) | Вы |

**Done:** логин → live A/V на Windows Docker. Без этого **не начинать** запись и полировку UI.

**Стоп-критерий:** если за неделю поток с звуком не заведён — не расползаться; ещё 2–3 вечера только на стрим, остальное стоп.

---

### Неделя 3 — UI управления и ночной режим

**Цель:** полный UC2 без записи на SD (или с записью-заглушкой).

| Задача | Кто |
|---|---|
| Экран Monitor: видео, mute, тумблеры | Вы |
| API: `POST /night-mode`, состояние | Вы |
| Ночной режим v1: CSS/canvas filter на клиенте | Вы (+ агент по мелочи) |
| Ночной режим v2 (если успеете): вызов `v4l2-ctl`/FFmpeg пресета — только на Pi | Вместе, можно буфер |
| Состояние «идёт запись» в UI (пока mock) | Вы |

**Done:** родительский сценарий кликабелен end-to-end на Docker.

**Учёба:** controlled components, простой state (без Redux), fetch + credentials.

---

### Неделя 4 — Запись + доставка на Pi по USB

**Цель:** кольцевая запись и первый запуск на железе.

| Задача | Кто |
|---|---|
| Запись сегментами (например 1–5 мин) + удаление старше 1 ч | Вместе (логика — вы понимаете цикл) |
| Один пайплайн захвата: live и record не дерутся за `/dev/video0` | Агент предлагает схему, вы утверждаете |
| `dotnet publish -r linux-arm64 --self-contained` | Вы |
| Скрипт `pack-for-usb.ps1`: publish + config example + README запуска | Вместе |
| На Pi: распаковка с USB, systemd unit или `run.sh`, C270 в USB | Вы на железе |
| Smoke: логин, стрим, mute, night, record | Вы |

**Done:** MVP критерии выполнены на Pi в домашней Wi‑Fi.

---

### Неделя 5 — Буфер (только если нужно)

- Стабильность Wi‑Fi / автостарт после reboot.
- Пресет камеры для ночного режима на Pi.
- Подправить CPU/latency (preset FFmpeg).
- Износ SD не оптимизировать до идеала — только «не падает».

Если неделя 4 закрыла MVP — буфер не обязателен.

## Порядок поставки на Raspberry Pi (процесс)

```text
Windows:  docker compose up  → разработка/проверка
Windows:  pack-for-usb.ps1   → D:\baby-monitor\  (флешка)
USB  →  Pi: скопировать в ~/baby-monitor
Pi:       ./run.sh   (или systemctl enable --now baby-monitor)
Телефон/ноут в той же Wi‑Fi → http://<ip-pi>:8080
```

Камеру и реальный mic проверять **только на Pi**; на Windows достаточно файла/паттерна.

## Распределение ответственности (кратко)

| Область | Вы | Агент |
|---|---|---|
| Auth, API, конфиг | основной | ревью/подсказки |
| React экраны | основной после каркаса | каркас, затыки, TS |
| Медиа/FFmpeg/compose | понимание + правки | первичная настройка |
| Кольцевая запись | понимание алгоритма | реализация деталей |
| Publish + USB pack | запуск скриптов | написание скрипта |
| Проверка на Pi | только вы | по логам/ошибкам remote |

## Риски по срокам

| Риск | Что делаем |
|---|---|
| Стрим A/V съест неделю 2 | Стоп-критерий; не начинать UI polish |
| React тормозит | Агент даёт тонкий UI; вы не учите экосистему целиком |
| Отладка только на Pi редкая | Максимум логики в Docker; на Pi — интеграция |
| Scope creep (HTTPS, алерты, IR) | В backlog после MVP, не в 4 недели |

## Backlog после MVP (не сейчас)

- HTTPS в LAN  
- Серверный night-preset + запись в «ночном» виде  
- Алерты по звуку  
- USB SSD вместо SD для записи  
- Упрощение до одного Docker-образа на Pi  

## Чеклист старта (сегодня / завтра)

1. Создать git-репозиторий/папку кода проекта (отдельно от `artefacts` docs или submodule — на ваш выбор).
2. Закрыть spike транспорта (вечер с агентом) → дописать выбор в `00-baby-monitor.md`.
3. Завести solution + пустой React.
4. Поставить в календарь **demo MVP = конец недели 4**.

**Целевая дата MVP:** 4 недели от старта недели 0.  
**Жёсткий дедлайн с буфером:** 5 недель.
